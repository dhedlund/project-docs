# Models

Data and domain models, and the often-messy story of how they map to physical
storage — MySQL, PostgreSQL, and MongoDB tables, views, and constraints, plus the
defaults and rules that live in application code rather than the database.

Model pages are intentionally **narrative**: they lead with what matters now and
push deprecated fields, historical quirks, and cleanup into collapsible sections.

Start a new page from `templates/model.md`.
